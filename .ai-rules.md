# Docs (Knowledge Base) AI Rules

This directory is the Single Source of Truth (SSOT) and Knowledge-Driven Development (KDD) hub for SafeChord.

## 1. Directory Structure

```text
Docs/
├── docs/         # Main documentation source files (Maps, Blueprints, Scripts, Brains).
│   ├── draft/      # Unverified scratchpads, ideas, unapproved docs.
│   ├── material/   # Static assets: images, diagrams, references.
│   ├── templates/  # KDD archetype boilerplate (empty scaffolds).
│   ├── meta/       # Documentation governance: standards/, proposals/.
│   └── archive/    # Deprecated historical docs (cold storage).
├── overrides/    # Custom theme overrides for MkDocs.
└── mkdocs.yml
```

## 2. Documentation Policies

- **SSOT Area**: The documentation here dictates the architectural and behavioral contracts for the entire system.
- **Divergence**: If the actual codebase implementation must deviate from the specs defined here, the Pioneer (Claude) must implement the fix first, and then the Settler (Gemini CLI) must perform **Documentation Reconciliation** to update these docs.

## 3. Document Archetypes (KDD Methodology)

- **Map**: Navigation & Aggregation (e.g., `safechord.knowledgetree.md`).
- **Blueprint**: Static Structure & Interfaces (API Specs).
  - `archetype.blueprint.microservice.md` — App-layer services: Business Requirements (What/Why), TDD Convergence Boundaries. Do NOT include endpoint paths, schemas, or test file paths.
- **Script**: Dynamic Workflows & Standard Operating Procedures (SOPs).
- **Brain**: Decision Records & Design Principles (ADRs).
  - `archetype.brain.infrastructure.md` — Infra-layer components (GitOps-managed): Design Constraints as red walls (budget/latency/capacity ceilings), Strategy/Policy definitions, Reference Snapshots (point-in-time, NOT SSOT). Do NOT duplicate manifest values.

### Layer-Specific SSOT Boundaries
- **App (Imperative)**: Docs own Why/What (Business Requirements, ADRs). Codebase owns How (endpoints, schemas, test cases).
- **Infra (Declarative)**: Docs own design constraints and architectural rationale. Manifests own current deployed state. Docs consolidate cross-cutting context scattered across YAML files, but do not replicate specific values.

## 4. Subdirectory Access Rules

### `draft/` — Unverified Content
- **No Auto-Loading**: Do NOT read or index files here unless the user explicitly provides a path.
- **Not Source of Truth**: If content here conflicts with `docs/*.md`, the latter wins.
- **Read-Only**: Do not modify drafts without explicit instruction.

### `material/` — Static Assets
- **Ignore by Default**: Do not load unless the user explicitly asks to analyze a specific asset.
- **No Modification**: Do not alter files here unless performing an asset optimization task.

### `templates/` — KDD Archetype Boilerplate
- **Scaffolding Only**: Read only when the user requests creating a new document or applying a template.
- **Context Exclusion**: Do NOT cite template content as architectural evidence — they are empty shells.
- **Immutable**: Do not modify templates unless the task is explicitly about template standardization.

### `archive/` — Cold Storage
- **Ignore by Default**: Do NOT include archived files when building context for current tasks.
- **Lowest Priority**: If a conflict exists between `archive/` and `docs/`, `docs/` is SSOT.
- **Historical Context Only**: Reference only when the user asks about history, previous versions, or evolution.

### `meta/` — Documentation Governance
- **Mandatory Pre-Read**: When creating or modifying any document under `docs/`, you MUST first read `meta/standards/taxonomy.md` and `meta/standards/style.md` to enforce consistency.
- **Archetype Awareness**: Match your editing approach to the document's `archetype` frontmatter value (map/blueprint/script/brain).
- **Proposals**: When the user raises a new architectural idea, suggest filing it as an RFC in `meta/proposals/`.
