# 疫情模擬器（服務藍圖）

> **類型**：藍圖（服務）
> **焦點**：這個服務對系統其他部分的承諾，以及它依賴什麼。
> **限制**：只寫現況。不寫檔案結構、函式庫或實作（看程式碼庫）。不寫欄位層級的形狀（看合約檔）。不寫理由（看[決策日誌](safechord.safezone.decisions.md)）。不寫沿革（看 [changelog](safechord.safezone.changelog.md)）。

## 1. 職責

*   **角色**：來源 / 產生器
*   **核心目標**：把一份靜態的歷史病例檔變成流動的資料。在開發與測試階段代替真實資料來源，並讓 pipeline 的其餘部分可以依需求以任意日期驅動。

## 2. 需求

每條需求都是系統其他部分會依賴的承諾。守住某條需求的測試會帶上它的 ID。所有服務共用的需求放在[服務標準](safechord.safezone.service.standards.md)，這裡不重複。

### SIM-R1：每日觸發重播一個日期
收到每日觸發時，模擬器必須為請求日期有病例的每個城市與區域送出一筆紀錄，病例數為該日期、城市、區域的加總。

#### 情境：有資料的日期
- GIVEN 來源資料中，某日期的同一城市與區域有數列資料
- WHEN 該日期被觸發
- THEN 送出一筆該城市與區域的紀錄，病例數為那幾列的加總

### SIM-R2：區間觸發重播範圍內的每個日期
收到區間觸發時，模擬器必須送出起始日到結束日（含兩端）每個日期的紀錄，每筆的組成方式同 SIM-R1。

#### 情境：只有一天的區間
- GIVEN 起始日與結束日相同的區間
- WHEN 它被觸發
- THEN 送出的紀錄與該日期的每日觸發相同

### SIM-R3：送出的並行量有上限
模擬器對攝入 API 同時進行中的請求數，必須永不超過設定的上限。

#### 情境：大量重播
- GIVEN 一次觸發產生的紀錄數超過設定上限
- WHEN 模擬器送出它們
- THEN 進行中的請求數永不超過上限

### SIM-R4：只送出有效紀錄
模擬器只能送出符合攝入請求規則的紀錄。一次觸發中有任何一筆違反規則時，必須一筆都不送，並回報失敗。

#### 情境：批次中有一筆壞紀錄
- GIVEN 一次觸發的資料中有一筆違反攝入請求規則
- WHEN 它被觸發
- THEN 沒有任何紀錄被送出
- AND 這次觸發回報失敗

### SIM-R5：回報成功代表每一筆都被接受
只有攝入 API 接受了每一筆紀錄，模擬器才能對該次觸發回報成功。

#### 情境：攝入 API 拒絕一筆紀錄
- GIVEN 攝入 API 對其中一個請求回應錯誤
- WHEN 這次觸發結束
- THEN 這次觸發回報失敗

### SIM-R6：沒有資料的觸發視為失敗
來源中沒有請求日期或區間的資料時，模擬器必須回報失敗，且不送出任何東西。

#### 情境：沒有資料的日期
- GIVEN 來源中沒有任何資料列的日期
- WHEN 該日期被觸發
- THEN 沒有任何東西被送出
- AND 這次觸發回報失敗

### SIM-R7：無效的觸發被拒絕
日期缺漏或格式錯誤，或結束日早於起始日的觸發，模擬器必須拒絕，且不送出任何東西。

#### 情境：結束日早於起始日
- GIVEN 一個結束日早於起始日的區間觸發
- WHEN 它到達
- THEN 觸發被判定無效而拒絕
- AND 沒有任何東西被送出

## 3. 依賴

| Channel | 方向 | 合約 | 另外假設 |
| :--- | :--- | :--- | :--- |
| 觸發 API | 提供 | `SafeZone/utils/pydantic_model/request.py`，由它的 Python 呼叫端共用。 | 無。 |
| 來源資料檔 | 讀取 | 沒有合約檔。檔案是 `SafeZone/data/<environment>/covid_data.csv`，依環境掛載。 | 每列是一批通報的病例，帶有日期、城市、區域與數量。服務執行期間檔案不會變動。 |
| 攝入 API | 呼叫 | `SafeZone/utils/pydantic_model/request.py`，與資料攝入器共用。 | 無。 |
