# KDD 協作模型變更紀錄

`practice.md` 是 `archetype: script`，只陳述當前生效的流程。這份文件裝的是那份文件結構上裝不下的東西：模型過去長什麼樣，以及它為什麼不再長那樣。

## 一則 entry 該寫什麼

三件事，沒有別的：

*   **決定** — 模型現在怎麼做。
*   **取代了什麼** — 先前生效的形狀。
*   **否掉了什麼** — 權衡過的替代方案，以及它們為什麼落選。

diff 摘要不屬於這裡。git 已經按 commit 持有改動與其理由；entry 存在的理由是裝那些沒有任何單一 commit 裝得下的東西——一個橫跨數個檔案、兩個 repository、以及一場沒有留下產物的對話的決定。

## 什麼時候寫 entry

**在版本收斂時寫，不是在改動時寫。** 一個版本還掛著調整期告示的期間，它是一次幾行地被修補，每次修補都寫一則等於把這份文件變成 churn log。告示撤掉之前，理由留在 `.ai-session-drafts/` 底下的草稿，以及 `git log -- docs/safechord.kdd.practice.md` 裡。

## 🔖 [v0.3.0] - 2026-04-23 → 2026-04-29

### 三引擎模型，跑在不同載體上

*   **決定**：三個席位跨兩個廠商。**架構師**持策略，**開拓者**（Claude Code）持實作與開 PR，**維護者**（Gemini CLI）持 PR 審查、合併、版本標記、關 issue 與文件對齊。席位由載體識別：廠商**就是**角色。
*   **取代了什麼**：沒有席位邊界的單一代理工作流。
*   **否掉了什麼**：當時沒有紀錄。當初支持這樣切的異質性論證——兩個廠商的失效模式不同，所以跑在不同引擎上的審查者不會繼承實作者的盲點——是從席位安排回推的，不是從任何寫下來的決定。

### 知識驅動取代規格驅動

*   **決定**：文件持有 Why、What 與 ADR；API schema、契約與測試案例留在 codebase 裡當作可執行邊界。TDD 成為收斂邊界，用來框住 AI 的實作自由度。知識地圖是實體的 Markdown 樹狀結構。
*   **取代了什麼**：由文件規定實作細節的規格驅動開發。
*   **否掉了什麼**：Vector DB / RAG 知識庫，理由是檢索損失——機率性的 chunk 相似度會讓代理重新發現它已經有的知識，或混用不相干的模組。實體樹狀結構讓父子關係是絕對的。

### 設計草稿從交接協定中分離

*   **決定**：兩個產物。交接往後帶進行中的工作；草稿往前帶一個尚未做成的決定，出現在實作開始之前。
*   **取代了什麼**：涵蓋兩者的單一協定。
*   **否掉了什麼**：當時沒有紀錄。
