# 時間伺服器（工具包藍圖）

時間伺服器是 SafeZone 生態系統中時間狀態的「事實來源」(Source of Truth)。它將模擬事件與視覺化從實際的時鐘時間中解耦。

## 1. 責任與定位
*   **時間樞紐 (Temporal Nexus)**：提供單一統一的系統日期 (`system_date`) 給所有元件，確保一個容器中的模擬器與另一個容器中的儀表板始終同步於同一個虛擬時刻。
*   **時間旅行代理 (Time Travel Agent)**：允許操作者將整個系統「傳送」到特定的歷史日期（用於重播）或未來日期（用於預測）。
*   **時間加速引擎 (Time Acceleration Engine)**：透過加速時間流來進行壓力測試，讓數天的疫情演變在數分鐘內完成模擬。

## 2. 核心邏輯：偏移演算法

系統時間並非以靜態值儲存。相反地，時間伺服器在每次請求時動態計算時間，以確保即使在手動更新之間也能持續前進。

### 2.1 計算公式
目前的系統時間由以下儲存在 Redis 中的關係推導得出：

$$ SystemDate = MockDate + (CurrentTime - MockUpdateTime) \times Acceleration $$

*   **MockDate**：由使用者定義的起始點。
*   **MockUpdateTime**：模擬日期最後一次設定時的實體時間戳記。
*   **Acceleration**：時間進展的乘數（預設為 1）。

### 2.2 持久化與午夜同步
*   **狀態儲存**：使用 Redis 確保時間設定在 Pod 重啟後仍然保留。
*   **午夜對齊**：為避免與日常維護任務衝突，基準偏移量在適當情況下會對齊實體午夜切換，確保虛擬日期隨著實體日期自然過渡。

## 3. 系統整合與可觀測性

### 3.1 時間的事實來源 (SSOT for Time)
SafeZone 中所有與時間相關的元件都必須從此服務取得目前日期：
*   **模擬器 (Simulator)**：使用 `system_date` 來決定要注入哪一段歷史 CSV 資料。
*   **儀表板 (Dashboard)**：使用 `system_date` 來設定趨勢圖與地圖的預設視窗。

### 3.2 可追溯性
*   **標準遵循**：遵循 Python Scaffold 中定義的通用服務標準（可追溯性與健康檢查）。
*   **需求**：每個對 `/now` 或 `/set` 的請求都必須處理並傳遞 `X-Trace-ID`，以確保與時間相關的狀態變更可追溯回原始 CLI 或 UI 指令。

## 4. 相依與控制

| 相依項目 | 類型 | 說明 |
| :--- | :--- | :--- |
| **Redis** | 儲存 | 時間偏移量與加速因子的狀態儲存。 |
| **szcli** | 控制器 | 操作者調整系統時間的主要推薦工具。 |
| **API 消費者** | 接收端 | 包含儀表板與疫情模擬器。 |

---
> **Agent 指令**：時間伺服器是資料一致性的關鍵相依項目。重構偏移邏輯時，請確保 Redis 資料結構保持向後相容，以防止系統層面的時間漂移。
